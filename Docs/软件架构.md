# 软件架构

## 概述

本工程是一个基于 Linux `termios` 的串口通信模块，向上提供简单的收发接口，向下封装设备打开、串口参数配置、`select` 监听与多线程接收。示例程序 `main.cpp` 演示了最小使用流程。

## 模块划分

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 示例入口 | `Code/main.cpp` | 初始化串口、启动接收线程、循环打印接收数据 |
| 串口核心 | `Code/Base/SerialPort.h/.cpp` | 串口打开/参数设置/发送/接收/接收线程 |

## 核心类

```
SerialPort
├── initSerial(portName, baudRate, dataBit, parity, stopBit)  # 打开设备并配置 termios
├── send(buf, len)                                            # 向串口写数据
├── startReceiveThread()                                      # 启动后台接收线程（detach）
├── getRecvData() -> RecvData                                 # 读取最近一帧接收数据
└── receive() / receiveThread() / setParameters()（内部实现）
```

## 线程模型

- **主线程**：调用 `getRecvData()` 轮询读取最新数据。
- **接收线程**（`receiveThread`，detach）：循环执行 `receive()`，通过 `select` 阻塞等待串口可读；读到数据后经 `setRecvData()` 存入内部缓冲区。
- **同步**：`fdMutex` 保护文件描述符，`recvDataMutex` 保护接收缓冲区，保证收发线程安全。

```
            ┌────────────┐   select/read    ┌──────────┐
 串口设备 ──┤ 接收线程    ├─────────────────▶│ 接收缓冲区 │◀──── getRecvData()
            └────────────┘   recvDataMutex  └──────────┘      主线程
```

## 关键设计点

- **拆包处理**：`select` 返回后延时 50ms 再 `read`，等待一帧数据收完，降低拆包概率。
- **阻塞模式**：`open` 后通过 `fcntl` 恢复阻塞读取，配合 `select` 使用。
- **数据有效期**：`RecvData.rxBuf` 指向类内部缓冲区，仅保证到下一次接收之前，调用者应及时拷贝。
- **资源管理**：析构时自动关闭文件描述符；初始化失败返回错误码并释放已打开的设备。
